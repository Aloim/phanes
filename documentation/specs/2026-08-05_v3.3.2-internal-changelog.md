# v3.3.2 internal Changelog entry (never released)

v3.3.2 was completed in full on the `v3.3.2-blueprompt-bugreport` branch and **never tagged, never merged and never pushed**. `origin/main` went from v3.3.1 straight to v3.4.0, so no user ever ran a v3.3.2 install and no public Changelog entry for it would describe a state anyone was ever in. Its content is folded into the v3.4.0 entry, where every fix it names is attributed **since v3.3.1**, that being the last published baseline.

This file exists because the *work* was real even though the *release* was not. The fourteen script fixes and three spec changes below were made under the v3.3.2 heading, reviewed under it, and recorded under it in SS00023; a reader tracing why a script changed should land on the reasoning as it was written rather than on a summary of it. **The entry below is byte-identical to the one deleted from `Changelog.md`**, including its version references and its Installed project impact block, both of which describe the unreleased intermediate state rather than anything a user can install.

## v3.3.2 (2026-07-28)

Patch release. A bug report from the Blueprompt project (`BUG-REPORT-2026-07-28-blueprompt-v3.3.1.md`), filed against spec v3.3.1, numbered eight findings. Five were genuine defects, fixed here: A1, A2, A3, and A7 (script bugs), plus **A6**, `new-file.ps1` alone never read the long-standing `docRoot` config key that `doc-index` and `doc-check` have honored since v2.6, so a `docs` target silently landed at the repository root instead of under the documentation tree, the same "handled at some call sites but not all" pattern the report's own A9 note names. Fixed with a guard that refuses a docs target resolving outside `docRoot` and names the corrected path, rather than auto-prefixing `docRoot` onto every caller's path, which would have changed path semantics for every existing caller to buy the same protection. The other three (A4, A5, A8) assumed config keys, `doc_discipline` (with its `index_exclusions` and `frozen_classes` sub-keys) and `pseudo_modules`, that had never existed anywhere in Phanes: not in the spec, not in the schema block, not in any script. They are adopted here as new features rather than credited as fixes, since a request for behavior nothing ever promised is not a defect. A5 also named a genuine defect alongside the invented key: `new-file` silently fell through to the generic source-comment branch on an unknown module instead of refusing, now closed by the module guard. Stated plainly so future reports are framed accurately, not as a rebuke. Verification during this release additionally found and fixed four more script bugs the report never named, nine script bugs fixed at that point, plus two Critical defects in the guards this release adds, both caught and corrected before shipping rather than found live. A tenth, unrelated to the report and predating v3.3.2 entirely, `loc-check.ps1` exiting non-zero outside a git repository and thereby breaking this release's own always-exit-0 advisory contract for scripts, was found during this release's own verification pass and fixed. A further four were found afterward by an independent Opus adversarial review that executed the scripts rather than reading them, bringing the total to fourteen script bugs fixed on this branch. None of this was found "post-release": `origin/main` is still the v3.3.1 distribution commit and this branch remains unpushed and unmerged, so every one of the fourteen was found and closed during review, not after any release. Three spec changes the same report proposed are adopted too: grouped-by-default batching, producer autonomy on small in-scope edits, and a flattened model and effort roster that retires `xhigh` and the per-agent effort-delivery bridge.

### Fixed
- **`doc-index.ps1` crash on documentation folders over 100 files.** The report's own diagnosis, silent script-scope corruption spreading to every folder processed afterward in the same run, was wrong: PowerShell function-scope assignment shadows the script-scope ceiling constant, it does not overwrite it, so sibling and later folders were never affected. The real defect is narrower and worse: `Build-Index`'s range-operator slice reads the ceiling constant by name after a same-spelled local array already exists in that scope (PowerShell variable names are case-insensitive), handing the range operator an array instead of an integer and throwing under `$ErrorActionPreference = 'Stop'`. It is a hard crash on the first oversized folder, not corruption carried into the folders processed after it. Fixed by renaming the local.
- **`doc-index.ps1` mojibaking non-ASCII DOC headers.** The header-detection read omitted `-Encoding utf8` where every sibling read in the file was explicit about it; non-ASCII text in a DOC header came out mojibaked in the generated index even though the source file itself was untouched.
- **BOM on every file `doc-index.ps1` and `new-file.ps1` generate.** `Set-Content -Encoding utf8` means UTF-8-with-BOM on Windows PowerShell 5.1, at four call sites across the two scripts. All four now write through `[System.IO.File]::WriteAllText` with a BOM-less `UTF8Encoding`, which also subsumes `new-file.ps1`'s existing `-NoNewline` intent.
- **`doc-check.ps1` undercounting lines.** `Measure-Object -Line` counts characters-as-lines within each string `Get-Content` returns, and an empty string measures zero, so every blank line contributed nothing to the total; a 525-line file with 199 blank lines measured as 326, hiding a real over-500-line ceiling breach. Fixed by counting the line array's own element count instead.
- **`doc-index.sh` rotating by filename (found during this release, not in the report).** Both `phanes.md` and the Windows implementation rotate the newest ~100 entries in by modification time, descending; the POSIX script rotated by sorted filename instead, contradicting its own header comment as well as the spec. Corrected to match.
- **`doc-index.sh`'s humanized-filename fallback (found during this release, not in the report).** `tr '-_' '  '` starts its argument with a dash, so `tr` parsed it as an option string and errored instead of translating, breaking the third-tier fallback (DOC line, then heading, then humanized filename) for every file with neither a DOC header nor a heading.
- **`doc-check` false-positive `NO-INDEX` on excluded trees (found during this release, not in the report).** A tree named in `index_exclusions` still had `doc-check` flag it `NO-INDEX`, since the exclusion only ever suppressed generation, never the check. `doc-check` now consults the same exclusion list, closing the exact false-positive noise the feature exists to remove.
- **`loc-check.ps1` undercounting lines (found during this release, not in the report).** The same `Measure-Object -Line` idiom fixed above in `doc-check.ps1` survived unnoticed in this sibling script: it counts characters-as-lines within each string `Get-Content` returns, so every blank line contributes zero, letting files with many blank lines escape the 500-line `OVER-CEILING` check silently, including through the `hook-size-check` PostToolUse path. Fixed the same way, counting the line array's own element count instead.
- **`loc-check.ps1` exiting non-zero outside a git repository (found during this release's own verification, not in the report; predates v3.3.2).** `$ErrorActionPreference = 'Stop'` turned a missing-repository `git ls-files` failure into a terminating exception, so the script died before reaching its own final `exit 0`, breaking this release's stated "advisory scripts always exit 0" contract. Not introduced by v3.3.2; reproduced live during this release's verification pass and fixed here rather than deferred again. Fixed by wrapping the call in try/catch: a missing repository now degrades to an empty file list and prints `loc-check: not a git repository, nothing to scan`, matching the POSIX sibling's existing behavior.
- **The same undercount class survived on POSIX, by a different mechanism (found during review, Opus adversarial review).** `doc-check.sh` and `loc-check.sh` both measured lines with `wc -l`, which counts newlines rather than lines: a file whose last line carries no trailing newline was undercounted by one, hiding a real ceiling breach exactly as A7 did. Fixed by switching both scripts to `awk 'END{print NR}'`, which counts the unterminated final line correctly.
- **`new-file.ps1`'s module guard diverged from POSIX on case (found during review, Opus adversarial review).** PowerShell's `-notcontains` and `-eq` are case-insensitive by default; the POSIX sibling's `grep -qxF` and `[ = ]` are not. `new-file CORE ...` was refused on POSIX and silently accepted, and stamped, on Windows even though `CORE` names no configured module. Fixed with `-cnotcontains` and `-ceq`, matching POSIX exactly.
- **Generated indexes linked to `_index.md` files that `index_exclusions` guarantees will never exist (found during review, Opus adversarial review).** Both `doc-index` implementations listed every subfolder, including excluded ones, as `- <name>/ : subfolder (see <name>/_index.md)`, while correctly skipping index generation for that subtree. An agent following the DOC DISCIPLINE header's own instruction to read `_index.md` first was sent to a file that could not exist. Fixed by applying the same exclusion test the generation path already uses before emitting the subfolder line, on both platforms.
- **`new-file.ps1` and `module-list.ps1` crashed on a malformed config (found during review, Opus adversarial review).** Both carried the unguarded `ConvertFrom-Json` already fixed in `doc-check.ps1`, `doc-index.ps1`, and `loc-check.ps1` earlier in this release; a stray trailing comma produced a raw stack trace instead of a clear message, locking a Windows project out of file creation through its only sanctioned creation path. Both now wrap the parse in try/catch: `new-file` degrades to defaults (an unparseable config carries no module list to enforce), `module-list` reports the parse failure and refuses, since an empty-list default would misstate a config that has modules but could not be read.

### Added
- **The `doc_discipline` config block**, a new optional block in `.phanes/config.json`: `index_exclusions` (folders `doc-index` skips, subtree included) and `frozen_classes` (folders `doc-check`'s `Is-Frozen` treats as exempt from the ceiling, in addition to its three built-in shapes, `archive`, `session-summaries`, and dated folders, which remain defaults, not replacements). Every clause of the normalization rule is identical across platforms except case matching (Windows matches case-insensitively, POSIX case-sensitively): a leading `docRoot/` segment is stripped if present, then matched as a docRoot-relative path prefix; a single-segment entry with no slash also matches a folder of that name at any depth, the same semantics the two hardcoded checks already had. Two Critical defects were caught in review before shipping: the first draft of the guard refused every source-module call in a project configured with no `modules` key at all, which would have locked such a project out of file creation entirely, fixed by scoping the guard to fire only when a non-empty module list is configured; and the POSIX docs-containment check was bypassable with a `..` path segment, letting a write land outside the documentation tree while reporting success (Windows was unaffected, since .NET's path canonicalization resolves `..` before touching disk), fixed by normalizing the path once and using that single normalized value for the containment check, `mkdir -p`, the overwrite test, and both writes.
- **Two `phanes new-file` guards** (**breaking**, see below): an unknown module name is now refused outright instead of silently falling through to the generic source-comment branch, and a `docs` target resolving outside `docRoot` is refused instead of writing wherever the literal path landed.
- **Grouped-by-default batching.** v3.3.1's grouping gate is replaced: per-step is no longer the default with grouping as an exception passing three conditions, a batch groups by default and sizes by step scope alone, never by tier, 3 steps for small-to-medium, 2 for medium-to-large, 1 for extra-large steps (expected rare), cap unchanged at 3. The tier-based sizing clause ("a T3 step runs as a batch of 1") is deleted; a T3 step is frequently extra-large and will often still run solo, but by scope, the honest determinant, rather than by tier as a proxy for it. One gate survives: overlapping working sets still force per-step, and ambiguity still resolves to per-step. The former security carve-out is replaced by a combined-pass contract: one security pass over every security-triggering step in a grouped batch, run once, after the Critic returns `pass` on all of them, verdicts keyed by step id exactly like the Critic's, and the auditor must affirmatively state it verified the grouped diffs share no interaction surface rather than assume it.
- **Producer autonomy on in-scope edits.** A producer archetype executing a dispatched task may now decide for itself whether an edit is small enough to just make, no permission round-trip first, and reports what it did and why in its normal report. No line caps, no class restriction. Two things this does not loosen: the Critic and security auditor keep their existing bounded 10/20-line self-fix caps unchanged, and the Executor must disclose its self-edits in its report so `close-verifier`'s applied-vs-approved check can still tell a disclosed deviation from drift.

### Changed
- **Model and effort roster flattened.** Every non-haiku agent now runs Sonnet 5 at `high`, with two named exceptions at Opus 5, `high`: the plan-authoring chain (the architect and the Critic reviewing it, through plan close, including any Reflect re-reviews within that pass) and the security-review specialization. The Critic is explicitly not a standing exception outside that plan-close window; every in-batch Critic pass runs at the general default. Scoped by **pass**, not by role, since the same architect and Critic archetypes run at Sonnet on every in-batch invocation.
- **`xhigh` retired; the per-agent effort-delivery bridge removed.** `high` is now both floor and ceiling for every non-haiku agent, so there is nothing left to lift: the resolution table, the `effort_class` field (everywhere, including `agent-definition.md`), and the entire CLI-spawn bridge that delivered elevation are deleted outright. The bridge existed only because the in-session Task tool ignores `effort:` frontmatter (anthropics/claude-code #43083, still open); `model:` frontmatter **is** honored natively, so the two remaining Opus contexts need no bridge at all. The four elevation triggers survive as a **record-only** obligation, the batch session summary still logs which fired, so the tuning signal outlives the spend mechanism it fed. The retired machinery, the resolution table, `effort_class` semantics, the spawn and resume command forms, and the never-spawn-downward rationale, is preserved verbatim for reinstatement in [`documentation/specs/2026-07-28_retired-effort-bridge.md`](documentation/specs/2026-07-28_retired-effort-bridge.md), together with the precondition for bringing it back. Session launch guidance becomes `--effort high`; any project launching at `--effort xhigh` should move to `high`.
